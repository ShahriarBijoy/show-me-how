# QA Checklist

## Must pass

- It is 16:9 landscape.
- Background is clean white.
- Xiaohei is present.
- Xiaohei carries the core action, not just decoration.
- No old-case composition copied; a new metaphor was invented for the current article.
- The image is absurd, creative, interesting.
- Clean and simple; subject no more than ~60% of the canvas.
- One image tells only one core structure.
- Labels are few, short, readable.
- Orange only for main path or arrows.
- Red only for emphasis, problems, reminders or results.
- Blue only for supplementary notes, feedback or system state.

## Failure signals

Regenerate or locally edit if:

- A title like "Common pitfalls / Workflow / System architecture / Roadmap" in the top-left.
- Xiaohei looks like a mascot, meme sticker or cute cartoon.
- The image looks like PPT, course slides, a formal flowchart.
- Too many elements, arrows, nodes.
- Text turns into paragraphs of explanation.
- Background has paper texture, shadow, gradient, beige, noise.
- Real UI screenshot or techy interface.
- Severe typos or unreadable labels.
- Too rigid, no absurd metaphor.
- Too similar to an old case composition in `assets/examples/`.

## Iteration moves

- Too ordinary: make Xiaohei the subject of the action; add a strange-but-valid metaphor.
- Too complex: delete nodes; keep one action and 3-5 short labels.
- Too cute: emphasize deadpan, blank serious expression, not cute, not mascot.
- Too PPT: remove title, borders, tidy grid and excess arrows; make it a hand-drawn scene.
- Too like an old case: keep the core meaning; swap the main object and Xiaohei's action.
- Wrong text: local edit first; if many errors, regenerate with fewer labels.

## Delivery judgment

A high-quality image should make the reader first think "that's a bit odd", then understand the structure within one second.

If at first glance it looks like a tutorial page rather than an absurd product sketch on blank paper, it fails.
