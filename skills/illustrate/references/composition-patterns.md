# Composition Patterns and Originality Rules

## Basic structure types

Pick one structure; don't mix too many.

### Workflow

Good for: input -> process -> output, content production, AI workflows, automation chains.

How: input on the left, the mascot or a strange machine processing in the middle, output on the right, `flow`-colored arrows for the main path.

### System part

Good for: information sources, filters, databases, renderers, a local part of an agent system.

How: draw only 3-5 core modules; the mascot takes part in one key action.

### Before / After

Good for: chaos/order, manual/automatic, scattered/gathered, anxious/stable.

How: chaos on the left, stable on the right, `flow`-colored arrow in between. Characters may be more exaggerated.

### Character states

Good for: user pain points, creator states, too many tools, information anxiety, stuck -> running.

How: 2-4 small states, one short label each.

### Concept metaphor

Good for: content factory, information warehouse, black box in the head, workflow machine, automatic daily report.

How: one big strange object or machine, a little input, one output. Must be memorable.

### Layered method

Good for: methodology frameworks, system layers, capability stacks, content-system layering.

How: stacked boxes, not a formal pyramid; the mascot hauls bricks or builds beside it.

### Map route

Good for: idea -> launch, user journey, content handoff path, learning path.

How: one winding path, few nodes, the mascot leading a line or walking.

### Mini comic panels

Good for: failure -> success, the real process, complaints, before/after using something.

How: 2-4 small scenes, one action per panel.

## Dev-doc anchors (what usually deserves a picture in a codebase)
- Before / after a change (the PR shot)
- The path a request takes (who calls whom, 3-5 nodes max)
- The one gotcha (expiry, race, retry, cache miss)
- State change (draft -> review -> merged; queued -> running -> done)
- Ownership / handoff (which service or team hands what to whom)

## Original-metaphor method

Reinvent the metaphor from the current article every time; never reuse old images.

### Three steps

1. Replace the abstract concept with a physical action: stuck, leaking, getting heavy, sorting, settling, fermenting, opening a door, folding, unpacking, flowing back.
2. Replace the system structure with a low-tech object: broken machine, cardboard box, drawer, water pipe, mailbox, strange dial, scale, well, ladder, odd workstation.
3. Let the mascot carry the action: not standing beside, but stuck in the machine, pulling the wrong line, guarding a gate, carrying, patching, weighing, holding the ladder, recording, stuffing things into some strange device.

### Object pool

- Cardboard box, drawer, old machine, funnel, scale, mailbox, door, well, ladder, water pipe, ball of string, sluice gate, turntable, black box, hole punch, pasta press, clothesline, odd workstation.
- Pick only 1-2 per image; don't pile up.

### Mascot action pool

- Pull, carry, stuff, scoop, press, weigh, sew, cut, twist, guard, push, catch, dismantle, mark, recycle.
- The action must serve the core meaning; don't be strange for the sake of strange.

## Anti-copy rules

Do not reuse a metaphor you used earlier in the same doc. Invent one per anchor from the article's own nouns.
